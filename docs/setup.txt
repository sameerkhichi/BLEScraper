BLEScraper setup
=================

This app runs on an iPhone. It reads the Colmi R09 over unencrypted BLE GATT, keeps the reading on the phone if the network is down, and POSTs JSON to an HTTP API. That API is the Arduino Uno Q, reached through your home network and port forwarding.

The iOS binary is built in the cloud with EAS, uploaded to App Store Connect, and attached to the TestFlight group named Internal. GitHub Actions does that on every push to main that changes code, and again on the 1st of every other month so the TestFlight build is refreshed before the 90-day expiry. GitHub's scheduler has no "every 60 days" interval, so every other month is the schedule.

FOR API/IP FORWARDING USAGE.
The Arduino URL, entered in the app under API settings. 
Example: http://203.0.113.10:8080/ingest
   The phone allows plain HTTP because the home server is not required to have a certificate.
   Optional API key is sent as the X-Api-Key header.


Install
-------

Node 22.14 or newer.

    npm ci

Dependencies are declared in package.json and locked in package-lock.json. requirements.txt in the repo root is the same direct dependency list.

Day-to-day JS check, from Windows:

    npm test
    npm run typecheck
    npx expo start

Bluetooth is a native module, so Expo Go cannot talk to the ring. A development or TestFlight build is required on the phone. This PC cannot compile the iOS app locally. EAS builds it.

First production cloud build
-----------------

    npx eas-cli login (verifies user credentials)
    npx eas-cli init (initializes production and writes project id)
    npx eas-cli build --platform ios --profile production (creates a cloud build)

The first build asks Apple credential questions and saves them for the GitHub Action. 
After it finishes:

    npx eas-cli submit --platform ios --profile production --latest

eas.json does not contain the App Store Connect app id or the Apple Team ID. EAS cannot read those two fields from environment variables. For a local submit, set ASC_APP_ID and APPLE_TEAM_ID in the shell, run node scripts/write-submit-ids.mjs, then submit. Do not commit the eas.json change that script makes.

Confirm the build shows up in TestFlight and installs on the phone. Later pushes to main do this from GitHub Actions.

GitHub Action
-------------

Workflow: .github/workflows/testflight.yml

Repository secrets, used only on the GitHub runner:

    EXPO_TOKEN
    ASC_APP_ID
    APPLE_TEAM_ID

The job writes the two Apple ids into its checkout of eas.json, then runs `eas build --platform ios --profile production --auto-submit`. That copy of the file is discarded with the runner. EAS builds the IPA, then submits it to TestFlight when the build finishes. The action does not wait for the compile, so GitHub minutes stay short. You can also run it by hand from the Actions tab.

Scheduled runs only happen from the default branch, which is main.

What the phone sends
--------------------

POST the saved API URL with Content-Type application/json.

    {
      "source": "colmi-r09",
      "syncedAt": "2026-11-06T19:45:00.000Z",
      "ring": { "id": "ios-peripheral-uuid", "name": "R09" },
      "battery": { "level": 64, "charging": false },
      "realtimeHeartRate": null,
      "heartRate": [{ "timestamp": "2026-11-06T19:40:00.000Z", "bpm": 72 }],
      "steps": [{ "timestamp": "2026-11-06T19:30:00.000Z", "steps": 120, "calories": 8, "distanceMeters": 90 }],
      "warnings": []
    }

Any HTTP status from 200 through 299 removes that reading from the phone queue. Anything else keeps it, in order, and the next sync or app launch tries again.

The ring clock is set to UTC on each sync. Heart-rate history is 5-minute samples. Step history is 15-minute blocks. A sync reads yesterday and today. "Measure heart rate" takes a live reading and sends that on its own.

The GATT service is 6E40FFF0-B5A3-F393-E0A9-E50E24DCCA9E. Writes go to 6E400002 and notifications come from 6E400003. Packets are 16 bytes. No pairing step.

Not in this first slice
-----------------------

Background sync while the app is closed. iOS limits that, and the current build only syncs while the app is open. The upload queue is the piece that survives a dropped network.
